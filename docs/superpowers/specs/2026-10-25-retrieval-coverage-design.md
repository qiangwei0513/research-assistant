# B 类候选覆盖与分批检索设计

用户要求正确率与得分优先，持续自主实施，不需要确认。官方 B 合同要求从授权库检索语义相关论文、遵守排除条件，并按相关性排序；漏检和误检均扣分。

现有实现有可复现的覆盖缺口：英文召回固定25篇，中文回退集合按摘要估算长度截掉后部，且上下文报错再次减少候选。这使成功解析的相关文献可能永远不可见。

选择完整候选分批筛选：BM25 只排序，零词项命中的文献也保留；按照实际 JSON 字符与每批最多12篇分批。相比查询翻译后仍截断，该方案不依赖词汇重叠；相比把全库压入单一提示，不靠无限扩大上下文。沿用同步 Gateway 与当前 trace，不引入并发请求。

每批使用原文摘要和片段，筛选结果只能来自该批。按剩余批数分配调用时间，保留5秒落盘；模型超上下文时拆批，单篇时缩短字段，绝不删除文献。非上下文失败记录覆盖缺口，继续其他批；已有有效结果保留，全部批失败则如实报错。时间耗尽不能声称全库无相关论文。

多批有结果时，可用剩余时间对已选文件及理由做仅排序调用；不得增删已选集合或改写证据理由。排序失败保留已证实结果与稳定顺序。单批保持原来一次调用路径。

本轮只保证成功解析候选的覆盖与预算内可恢复执行，不声称支持任意大小库在180秒内完整阅读；超预算/失败覆盖通过日志明确记录。解析器/OCR、D算法、C/E内容不在本轮修改范围。
