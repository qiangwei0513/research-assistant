# 赛事 Agent 时限与失败恢复加固

日期：2026-10-24。用户授权依据赛事文档直接推进、同步文档，无需逐项确认。

## 目标与边界

保持现有 Python 单服务、官方 AgentRuntime、八字段输入与五类直接 JSON 输出。解决代码审查发现的实际超时和恢复缺口；保留 D 源码原样保存、当前会话生成、正式 helper 权威结果。平台 R03 和官方成绩仍必须由真实平台记录证明。

## 方案选择

- 只在解析循环前检查时间成本低，但无法中断卡住的单篇 PDF；不采用。
- 线程超时不能停止解析工作，可能继续消耗 CPU；不采用。
- 采用可终止的独立解析子进程，父进程掌握整批剩余时间；无预算的本地直接提取接口保持兼容。解析失败记录真实状态，继续处理其他授权材料。

D 生成使用扣除预留后的子 Deadline；自测 timeout 改为整批共享预算，不能每个样例重复领取。生成失败保留前一份完整源码；没有可用源码时输出合法失败答卷。正式运行仍预留落盘时间。C/E 若已有合法初稿，修复失败应保留原稿而不是整题报错（由审查和回归确认后落实）。

## 验收

单篇解析挂起可终止且无子进程残留；损坏/不可读文件不阻断其余材料。D 多样例总超时有界，生成不会领取正式运行的预留，失败保留原样源码。回归测试、默认完整测试、ruff、镜像内非 root HTTP 冒烟通过后更新交接。每个代码修改批次同步文档。源码、镜像与正式平台证据分别记录。

## 执行决定

沿用干净的 `p1-minimal-service` 分支原位工作：项目测试、材料和交付归档使用相邻目录，额外 worktree 会改变这些既有路径。不开新产品范围，不覆盖官方材料，不推送或启动未知平台评测。缺少平台入口/会话时如实记录 R03 的外部依赖。
