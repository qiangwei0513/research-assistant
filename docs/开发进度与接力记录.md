**关键决定及依据**：

1. **自建 FastAPI app，不用 `AgentRuntime`**（当时的判断）——SDK 的 `/solve` 合同与赛题一冲突。**2026-10-24 已更新**：组委会要求入口必须由 `AgentRuntime` 启动，改为保留官方 app/`Telemetry`、只替换 `/solve` 路由；该条仅保留为 P1 历史。
2. **只复用 SDK 的 interceptor 与 `Telemetry.session()`，本地降级 no-op**（工程选择）——保留平台可能用于 30% 复核的 trace，同时本地无 SDK 也能跑。
3. **混合执行模型**：async 路由 + `anyio.to_thread` + 同步 handler（工程选择）——D 类的阻塞子进程与 monotonic 预算天然契合。
4. **响应体直接复用落盘 bytes**（官方要求「同一结果」）——FastAPI 默认 JSONResponse 会用不同分隔符重新序列化，做不到逐字节一致。
5. **`/health` 只在输出根不可写时 503**（工程选择，Q03 待确认）——healthcheck 失败会让整轮评测起不来，代价远大于单题报配置错误。
6. **`from_env` 不因网关问题抛异常**（工程选择）——同上理由；网关错误改由 `require_gateway()` 在解题时抛。
7. **路由错误先于配置错误**（工程选择）——网关未配置时注入 `UnavailableGateway`，使 B/C/D/E 报 501（未实现）而非 500（配置缺失），诊断价值更高。
8. **预算必须有限正数**（官方要求推导）——`nan` 与任何值比较均为 False，只写 `> 0` 会让整层时间守卫静默失效。
9. **`assert_own_expert_file` 用锚定 fullmatch**（官方要求「不得访问其他队伍报告」）——非锚定 `endswith` 会被 `ZZZZ-综述-<本队>.md` 这类诱饵骗过。
10. **pytest 默认 `filterwarnings = ["error"]`**，只按消息前缀精确豁免三条 starlette 0.37.2 与较新 `python_multipart`/`anyio` 版本差导致的第三方警告；`PytestUnraisableExceptionWarning` 仍受 `error` 管辖，本项目自身的 unraisable 异常照样失败。

**关键决定及依据**：

1. **PDF 解析选 `pypdf==6.21.2`**（N01 已关闭）——纯 Python、**零强制依赖**（crypto/image/full 全是 extras），不需要平台专属 wheel，从 macOS/arm64 构建 linux/amd64 一致。已在隔离环境实测能正确提取正文。排除 `pdfminer.six`（需 `cryptography>=36`，C 扩展）与 `PyMuPDF 2.0`（AGPL-3.0/商业双授权，且拖 onnxruntime/networkx 等重依赖）。
2. **不建跨题缓存**——官方规则是每题独立容器与会话，缓存没有复用对象，建了就是死代码。总纲 §5.1 提到的缓存键设计因此未实现。
3. **B 类跨语言回退**——官方 `input` 是中文而论文是英文，纯 `[a-z0-9]+` 分词对中文查询产不出 token，词项召回恒为空、B 类会永远返回空数组（15 分归零）。改为：查询含 ≥3 个拉丁词项且有召回时走 BM25；否则把全部可用材料的摘要交给模型基于原文判断。两条路径都按 24000 字符预算截断。
4. **理由长度不作硬失败**——中文理由天然紧凑，一条理由偏短就让整题变 502 等于用 15 分赌长度。改为只告警，非空仍由 `results.retrieval_result` 强制。
5. **模型返回的 filename 一律不信**——必须回溯到授权集合；仅大小写不同映射回论文库**原始**名称（评分大小写等价但文件系统区分大小写）；越界与编造的文件名直接丢弃并记日志。
6. **C/E 各只做一轮定向修复，且仅在问题数确实变少时采用修复稿**——多轮自评不等于真实实验，也不能吃掉整题预算；修复反而变差时保留原稿。
7. **C/E 无可用材料时抛 `MaterialUnavailableError`（422）而不是返回空壳**——C/E 没有 `failed` 状态，返回伪装成功的空壳报告是总纲明令禁止的。
8. **D 类 figures 是对象数组**（`path`/`caption`/`x_label`/`y_label`/`legend`）——P1 按字符串数组实现会把 helper 的真实答卷判非法，直接丢掉 40 分。已按官方输出规范修正。
9. **D 类三项指标的 name/unit 从本题 `input` 解析**（`name=X，unit=Y` 形式）——官方明确「当前 D 题已将三项指标名称、单位写入 assigned/<case_id>.json 的 input」。失败答卷也保留题目指定的名称与单位、`observed` 填 null；解析不出时用带序号占位名并记 error 日志，**绝不臆造官方指标名**。
10. **D 类必须自测，且自测在调用 helper 之前**——实测发现真实网关生成的源码用了 `re.findall` 却没有 `import re`，而官方 AST 检查只验语法与入口函数名，这类源码能通过来源准入却运行即 NameError；helper 一执行就锁源、锁源后不得换源码，整题 40 分归零。自测用受限子进程（独立解释器、`-I` 隔离、无 shell、`RLIMIT_CPU/AS/NPROC`、墙钟超时、cwd 锁定本队 work 目录），**不依赖 Docker**，因为线上是否有 Docker socket 属总纲 Q05 未确认项。
11. **提取失败或自测失败只能让同一会话模型重新返回完整版本**（最多 3 次），提示里明确要求自包含 import；绝不本地补码、不拼多个回复、不应用 diff。
12. **自测三次仍失败时仍然调用正式执行**——不调用必然 0 分，调用还可能拿到输入处理、基线与图表的部分分；该决定记 warning 日志。
13. **`PersistedResult`：helper 自己写的结果文件是权威产物**——只回读校验、不重写、不重新序列化，HTTP 直接返回 helper 写下的那份字节。总纲要求「优先保留 helper 已保存的真实结果，后续解析失败不能用占位失败结果覆盖它」。
14. **`PersistedResult` 放在 `runtime/persistence.py` 而非 `solve.py`**——否则 `solve → registry → reproduction → solve` 成环。
15. **Dockerfile 必须 `mkdir -p /output` 并 `chown 1000:1000`**——基础镜像里 `/output` 不存在；非 root 运行时若不可写，`/health` 报 503，基础镜像 HEALTHCHECK 连续 6 次失败会让整轮评测起不来。
16. **镜像只补 `pypdf`，且用 `--no-deps`**——其余运行时依赖基础镜像已按锁定版本预装，`--no-deps` 避免扰动该集合；包通过 `PYTHONPATH=/app/src` 显式导入，工作目录切到 `/output` 后仍可用。

**已知问题 / 失败尝试 / 不要重复的操作**：

- **B 类的排除条件必须靠「两阶段筛查」才守得住**。实测真实模型会把题目明确排除的论文也选进来（4 篇全返回），按公式每篇误检扣 0.75 分。修复方式是把 `excluded` 写进输出合同强制模型先做排除推理（程序随后丢弃该字段），并在系统提示里写明评分不对称与「宁缺勿滥」。改提示时**不要**删掉 `excluded` 这一步——已有单测钉住。
- **模型偶尔不按输出契约返回**（实测约 5 次 1 次返回自由文本）。已加最多一次的有界重问（`runtime/modelcall.py`），预算不足 12 秒时不重问。不要把它改成无界重试。
- **E 类（Idea）生成耗时是当前最大的时限风险**。八次真实实测分布 **57.1 / 60.9 / 112.7 / 113.0 / 139.3 / 146.8 / 166.9 / 176.1 秒**，中位约 120s，而单题上限按 D 类材料是 180s（非 D 类的精确限时属 Q03 **未确认**）。已做三重缓解：正文上限与每节字数预算（提示词层，模型**并不总遵守**，实测仍写出过 4400 字符）、E 类证据包从 6000 收紧到 2200 字符/篇（输入侧压 prefill，实测把最差值从 176.1s 降到 112.7s）、预算不足 20s 时跳过修复轮。**不要**改用调小 `max_tokens` 来硬截断：C/E 截断会丢掉结尾的 `## 参考文献`，且 `finish_reason` 变成 `length` 会触发 `GatewayError` → 502 → 整题 0 分，比慢更糟。联调时必须实测正式模型的 E 类耗时，若逼近上限，优先考虑进一步压缩证据包或合并小节，而不是截断。
- **派题记录只作提示，绝不因它拒答**。组委会清单说明平台自己会校验 dispatch/assigned 与请求的一致性，且 Single 模式只保证当前题文件可读。早先我们在装配上下文时校验全部 11 个 assigned 文件，平台若只挂当前题就会让整轮 422。现在只核对**当前题**文件，结构/归属/哈希/缺失问题一律记 warning 后继续；`dispatch.json` 结构损坏也只降级为 `dispatch=None`。安全边界仍在：材料路径与结果路径的授权校验没有放松。
- **材料解析必须有时间上限**。PDF 解析是模型调用前唯一无界步骤；若平台把整库（几十上百篇）放进 `materials`，全量解析可能直接吃掉 180 秒。现在 B/C/E 解析都带 `time_budget_seconds`（按剩余预算最多 60 秒），超限记 `documents.time_budget_exhausted` 后停止，把时间留给模型与落盘；库小的时候完全不受影响（707 测试含零预算回归）。
- **平台变量族宁可宽容也不能误判**。两组 Gateway 变量按整组探测。平台同时注入推荐组与兼容组；两组都完整但取值不一致时，**优先用推荐的 `CHALLENGE_*` 组并记字段级 warning**，绝不再整个禁用网关（那会让所有模型题归零）；`base_url` 末尾斜杠视为等价。队伍目录按组委会口径取 `RESEARCH_WORKSPACE_TEAM`，其次本地 `TEAM_NAME`；**不用 `TEAM_ID`**（它只是遥测身份，拿它当目录会写到平台不读取的路径），两者都没有时**明确报错**，绝不猜目录。正式联调第一天先看启动日志的 `gateway_family` 与首次落盘路径，确认变量族与队伍标识都取对了。
- **平台要的 Trace 是 `session → task → llm` 三层，少一层就报 `AGENT_RUNTIME_TRACE_MISSING`**。只开 session 与 llm 时平台会明确说「未收到本次任务的有效 AgentRuntime 运行追踪」——它核验的是 `task()` 这个「solve 调用」span，而 SDK 的 `task()` 必须在 `current_session()` 内进入（`@contextmanager`，进入时才校验）。`runtime/http_solve.py` 现在写成 `with trace_session(...), task_span():`，并且 `flush_telemetry()` 放在 `finally`、**在 session span 结束之后**——放里面会导不出顶层 session。交付镜像里 `trace_session` 使用的是官方 `runtime.telemetry`（由 `official_runtime.use_instance` 注入），绝不能再构造第二个 `Telemetry`。SDK 的 `task_id` 用平台传输头 `X-Research-Task-ID`（缺失才退到 case_id），`case_id` 同时写到 session 根 span 与 task span；`session_id` 用 `X-Session-ID`；只透传 `traceparent`/`tracestate`，`Authorization`/`Cookie` 绝不进遥测。改这段时先跑 `tests/unit/test_official_runtime.py` 与 `tests/unit/test_telemetry_llm.py::test_solve_emits_session_task_llm_topology`，假 SDK 会在错层直接抛错。
- **提交平台时不要传错文件**。基础镜像归档 `agenthack-base-1.1.1.tar`（175,757,824 字节、SHA `57ce57ff…f7d2`）与交付归档只差约 1.3MB，肉眼极易混淆；平台对基础镜像的报错是「Agent 容器启动后退出」，因为它的 CMD 就是故意 `exit 1`。上传前用 SHA-256 核对。另：`docker save` 产出的归档权限是 `600`，macOS 的文件选择器会把它置灰成不可选；交付前需 `chmod 644`（已做，并另建了短名硬链接 `../agent-upload.tar`，同一 inode、同一 SHA）。
- **D-05 的预算余量很薄**。实测：两次生成（第一次违反不变量、第二次通过）共耗时 **113.3s**，而整题只有 180s，预留为 55s 正式运行 + 12s 自测 + 5s 落盘。也就是说 D-05 只剩约 8s 缓冲。若正式模型更慢或需要第三次生成，`deadline.remaining() - reserve < MIN_GENERATION_SECONDS` 会提前 break，只能带着未通过自测的源码去正式执行（记 `reproduction.source_used_despite_failed_self_test` 与 `proceeding_without_self_test` 两条 warning）。联调时必须实测正式生成耗时，并据此在「调小 `RESERVE_RUN_SECONDS`」「收紧提示让模型少写代码」「下调 `MAX_GENERATION_ATTEMPTS`」之间取舍。
- **生成源码不得进仓库、不得进镜像**。开发期验证用的源码放在 `work/generated/<case>.py`（`work/` 已被 gitignore，`.dockerignore` 也不含它）。已加测试 `test_generated_source_is_never_prewritten_into_the_repository` 守住「`src/` 内不得出现 `def run_experiment(`」。
- **结构性检查发现不了时序语义错误**。D-05 的换流 setup 漏算是实证：任务守恒、start<deadline、end<=horizon、served_ms 覆盖零服务流全部成立，227 项断言全绿，而算法是错的。凡是「状态如何在事件之间保留」这类规则（空闲不清除上一流、成功即预留、拒绝不回队），都必须有能把状态与派发次序对上的检查，或用独立实现逐事件比对。
- **不要在 D 类跳过自测**。这是本轮代价最高的教训：通过来源准入 ≠ 能运行，也 ≠ 算法正确。实测抓到三类只有自测+不变量才能发现的错误——`re.findall` 而没 `import re`（运行即 NameError）、并列类别未取字典序最小（D-01）、任务重复进入 trace 与 dropped（D-05）。helper 一执行就锁源。
- **自测必须比对算法不变量，不能只看结构**。`reproduction/invariants.py` 是从官方 method 推导的可独立复核项，不复制完整参考实现、不计算任何官方指标。改 D 类相关代码前先跑 `scripts/validate_d_invariants.py`。
- **不要把自测结果 print 到 stdout 再截断**。曾截断到 4000 字符，D-02 的 27 行搜索记录（26366 字节）必然解析失败，造成假阴性并白耗一轮 85 秒重生成。现改为写文件、不截断。
- **不要靠「stdout 最后一行是 JSON」取结果**。生成源码自己 print 调试信息就会取错行。
- **不要用贪婪正则从参考文献行里抠 PDF 文件名**。字符类含 `.` 与空格会把作者与标题一起吞进来，导致合法引用被误判为未知材料而整片丢弃。现改为先在授权文件名集合里精确子串匹配（能正确处理含空格、中文、`+` 的真实文件名）。
- **不要用全文关键词判断 E 类「基线与改进组」是否合格**。小节标题本身就含「基线」二字，等于永远通过。现改为只在该小节正文内判定。
- **`figures` 不是字符串数组**，是 `path/caption/x_label/y_label/legend` 五键对象数组。
- **PDF 提取会在短语中间断行、也会拆开行尾连字符断词**。定位证据必须走 `normalize_for_search`，朴素子串匹配跨行必然失败，进而导致 C 类漏引用甚至编造页码。
- **命令不要用 `cmd | tail`**：管道会吞掉 pytest 的非零退出码，曾导致带着一个红测试提交。用 `cmd > log 2>&1; echo $?`。
- **警惕隐形同形字符**：`selftest.py` 某行标识符曾含非 ASCII 同形字符，导致 `grep` 匹配不到而 ruff 报 F821、AST 却显示绑定存在。按字节重写该行即解决。
- **`_generate_source` 的预算预留是 55s（正式运行）+ 12s（自测）+ 5s（落盘）**。不要把预留调小——那是 D-05 唯一的安全边界。
- 不要往 `pyproject.toml` 加 `ignore`/`per-file-ignores`，也不要加 `# noqa`：本项目已五次因未授权抑制被打回。中文代码库需要的 `RUF001/002/003` 与 `E501` 已一次性处理完。
